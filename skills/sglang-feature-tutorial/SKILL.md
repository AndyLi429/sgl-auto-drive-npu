# SGLang 特性源码导读

为零基础开发者建立从“为什么需要它”到“下一步读哪段代码”的跳板。教程应帮助读者建立正确的系统心智模型，而不是复述文件列表或把通用推测写成 SGLang 事实。

## 确定范围与源码快照

从请求中提取特性、目标仓库、读者水平、期望深度和输出位置。默认面向 SGLang 初学者，覆盖设计概览与一条关键调用链；用户要求 NPU 时，再追踪 SGLang runtime 到 `sgl-kernel-npu`、`torch.ops.npu` 或 DeepEP 的边界。

优先使用用户现有 checkout，记录仓库、分支、HEAD 和采集时间。若请求涉及“最新”代码，核对 `sgl-project/sglang` 或 `sgl-project/sgl-kernel-npu` 的默认分支。存在 `.codegraph/` 时，先用 CodeGraph 定位符号和调用关系；否则使用 `rg`，再阅读命中的实现、调用者和测试。

先区分两类内容：

- **通用概念**：可用明确的“概念模型”表述，例如 KV cache 为什么能复用前缀。
- **版本相关事实**：类、函数、文件、配置、算法、指标和时序必须来自当前源码、测试或官方文档，并附路径、符号和快照。

没有证据时写“待源码确认”，不要以熟悉的 vLLM/CUDA 实现替代 SGLang 的实际行为。

## 溯源方法

先回答用户问题，再选择最短的真实路径。常见路径是：

```text
用户配置或请求
  -> server / registry / factory
  -> scheduler 或 feature consumer
  -> state、cache 或 memory manager
  -> model runner / backend / kernel boundary
  -> 测试、指标或日志
```

对每个关键跳转记录“输入、输出、状态变化、关键不变量、下一跳符号”。不要假定所有特性都经过 scheduler，也不要把辅助工具类称为热路径。只有真实调用链跨过 NPU 边界时，才说明组件属于 SGLang、`sgl-kernel-npu`、DeepEP 或 CANN/torch-npu。

## 教程结构

读取 [references/tutorial-template.md](references/tutorial-template.md) 并按需裁剪。按以下顺序讲解：

1. **先讲问题和收益**：一句话定义、适用场景、非目标和代价。
2. **补足最少前置概念**：首次出现的术语用中文解释，英文术语保留在括号中；不要假设读者已理解 scheduler、prefill、KV cache 或 graph capture。
3. **给出系统地图和一次请求路径**：用图展示组件关系，再用代码证据展开关键节点。
4. **建立代码阅读路线**：每一站说明“为什么读、看什么输入输出、读完后跳到哪里”。
5. **落到实践**：仅在官方文档或源码证实后写配置、日志、指标、测试或最小实验；未在当前环境运行的命令明确标注为未执行。

代码片段只截取支撑结论的最小段落，前置文件路径、符号和快照；随后解释其职责与调用位置。避免大段复制源码，也不要用伪代码冒充项目实现。

## Mermaid 图表

默认使用两张图：系统架构图和请求/数据流图。只有确实能降低理解门槛时再增加时序图、状态图或数据结构图；每张图只回答一个问题，控制在约 8–12 个节点。

使用 **`mermaid-syntax`** 校验图表：使用 `flowchart`，给含特殊字符的标签加双引号，使用安全的英文节点 ID，不把 `end`、`default` 等保留字作为 ID；时序消息中的分号写为 `#59;`。把源码符号放在图注或旁注，避免塞满节点。若有 Mermaid 渲染器，实际渲染；否则执行语法检查清单并说明未做渲染验证。

## 输出与质量门槛

默认在回复中生成 Markdown；只有用户明确要求落盘时才写文件，未给路径时使用当前工作目录下的 `sglang_<feature>_tutorial.md`。

交付前确认：最终文档不含模板的 `<...>`、`已核验` 等占位文字；所有“核验”结论均已由其相邻路径、符号和快照支持。

| 检查项 | 要求 |
|---|---|
| 初学者可读性 | 在源码名词前先解释问题、概念与数据流 |
| 事实可追溯 | 每个项目实现结论有路径、符号和快照/版本 |
| 调用链 | 至少一条从入口到状态或执行边界的真实路径 |
| 图表 | 2–4 张，各自表达不同的问题且符合 Mermaid 语法 |
| 深入入口 | 给出按因果顺序阅读的代码索引、测试或可观察证据 |
| 不确定性 | 推断、未验证命令和版本差异显式标出 |

## 常见误区

| 误区 | 正确做法 |
|---|---|
| 先罗列类和文件 | 先解释它解决的用户问题，再引到代码 |
| 用其他项目的术语补全细节 | 仅将其作为概念对比，SGLang 结论必须回到源码 |
| 一张图囊括所有模块 | 按架构、生命周期、状态拆图 |
| “缓存命中”就等于不计算 | 明确命中范围、未命中后缀、内存代价和指标口径 |
| 只给路径，不给阅读目的 | 每个入口写清输入/输出、不变量和下一跳 |
